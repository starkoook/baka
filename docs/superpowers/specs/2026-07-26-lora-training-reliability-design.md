# LoRA 训练可靠性改进设计

日期：2026-07-26

状态：用户已批准实施

## 目标

让 Baka TOOLS 的常规 LoRA 训练路径真正复用 `lora-rescripts v1.6.2`，优先解决会改变训练结果或导致任务无法启动的问题。本轮不扩展高级训练类型，也不直接运行耗时的正式训练。

## 已确认问题

1. 用户在“本地底模路径”中选择的文件只写入 `baseModel`，提交配置仍读取 `pretrainedModel`，因此本地模型可能没有进入训练任务。
2. 应用优先发现内置源码目录，但内置目录没有完整运行环境；当前电脑上已有的参考目录 `D:\comfyUI\lora-rescripts-study` 反而更接近可运行状态。
3. 开始训练前只检查字段是否为空，没有检查本地模型、数据集和输出目录是否真实存在。
4. 后端启动后固定等待两秒，机器较慢时仍可能在后端未就绪时提交任务。
5. 运行时扫描只确认“存在任意已安装环境”，启动时却没有明确使用这个已安装环境。

## 方案比较

| 方案 | 优点 | 缺点 |
|---|---|---|
| 只修本地底模传参 | 改动最少 | 环境选择和后端启动仍可能失败 |
| 直接写死参考目录 | 当前电脑最快可用 | 换电脑或移动目录后失效 |
| 有效目录自动选择 + 完整预检（采用） | 当前电脑可复用参考环境，同时保留用户设置和跨电脑能力 | 比单点修复多少量检查代码 |

## 设计

### 1. 底模来源

- 保留 HuggingFace/手动路径输入和本地文件选择。
- 本地文件一旦选中，训练配置、配置预览、日志和预检全部使用该文件。
- 点击模型预设时清空旧的本地文件选择，避免用户以为已经切换模型但仍在使用旧文件。
- 页面明确提示“本地底模优先”。

### 2. 训练仓库选择

仓库按以下顺序选择第一个包含 `gui.py` 的有效目录：

1. 用户已经保存的训练仓库目录。
2. 当前电脑上的参考目录 `D:\comfyUI\lora-rescripts-study`。
3. Baka TOOLS 内置的 `lora-rescripts-main`。
4. 应用数据目录中自动下载的仓库。

参考目录不存在时自动跳过，不影响其他电脑使用。用户设置始终具有最高优先级。

### 3. 启动前检查

开始训练后依次检查：

1. 有效底模不为空；选择本地底模时文件必须存在。
2. 训练数据集目录存在。
3. 输出目录存在，输出名称不为空。
4. 训练仓库有效，并且至少有一个已安装运行环境。
5. 启动明确选中的已安装运行环境。
6. 轮询后端状态直到可访问或超时，不再固定等待两秒。
7. 调用 lora-rescripts 自带的训练预检。
8. 预检通过后备份配置并提交任务。

任一步失败都停止提交，并在训练日志中给出可执行的处理建议。

### 4. 验证边界

自动验证覆盖底模选择、目录检查、仓库优先级、后端等待、类型检查和项目构建。本轮不自动下载大型依赖，也不启动正式 LoRA 训练；真实 `.safetensors` 产出留到用户提供可用数据集和底模后做小规模验收。

## 成功标准

- 选择本地 `.safetensors` 后，提交 JSON 中的 `pretrained_model_name_or_path` 与所选文件完全一致。
- 参考目录存在且用户未设置其他目录时，运行时扫描使用参考目录。
- 本地底模、训练集或输出目录不存在时不会提交任务。
- 后端未就绪时持续检查，超时后明确失败，不再盲等两秒。
- 启动后端时使用扫描结果中实际已安装的运行环境。
- 新增测试、全部现有测试、类型检查和构建均通过。
