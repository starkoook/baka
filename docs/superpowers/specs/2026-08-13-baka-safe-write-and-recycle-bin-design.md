# 图库安全写入、撤销历史与回收站设计

## 目标

让 Baka TOOLS 在保存标签/元数据、删除图片、移动或复制图片时，做到：

1. 失败不破坏原文件。
2. 改错可以撤销。
3. 删除的图片和标签可以恢复。
4. 批量操作失败时，用户能看到失败清单。

这是一个基础能力，后续中文标签匹配、打标升级都会复用它。

## 范围

本轮实现：

- 安全写入标签文件、caption、元数据缓存。
- 每次覆盖前自动保留历史版本，默认每个文件保留最近 10 个版本。
- 图片/标签删除进入应用内回收站，默认保留 30 天。
- 回收站内可查看、恢复、彻底删除、清空过期项目。
- 移动/复制图片时，图片与同名标签/数据库记录一起处理，失败自动回滚。
- 批量操作返回成功、失败、跳过数量，并保留失败路径列表。

本轮不做：

- 接入 Windows 系统回收站。
- 云备份或跨设备同步。
- 无限版本历史。
- 版本 diff 或并排比较。

## 现状

当前相关代码：

- `electron/main.js`：提供 `fs:saveCaption`、`fs:moveImages` 等文件操作 IPC。
- `electron/ipc/gallery.js`：图库数据库、缩略图、标签和元数据缓存。
- `electron/ipc/annotation-save.js`：标注保存。
- `electron/ipc/paths.js`：统一数据目录 `D:\BakaTOOLS`。
- `src/stores/gallery.ts`、`src/views/Gallery.vue`：图库前端调用。

现有文件操作部分场景直接写文件或移动文件，缺少统一的原子写入、版本保留和回收站机制。

## 架构

### 新增主进程模块

#### `electron/ipc/safe-file.js`

负责所有“先写临时文件，再替换目标文件”的操作。

核心逻辑：

```text
写入内容
  -> 在同目录创建唯一临时文件
  -> 写入临时文件
  -> 如需保留历史，先把原文件复制到版本目录
  -> 用替换/移动覆盖原文件
  -> 失败时清理临时文件，原文件保持不变
```

关键点：

- 临时文件名使用短前缀，避免长文件名超过 Windows 限制。
- 同一路径使用进程内锁，避免并发写坏。
- 目标文件不存在时直接移动临时文件。
- 目标文件存在时优先使用原子替换，失败再降级为移动。

#### `electron/ipc/file-history.js`

负责保存和恢复文件历史版本。

规则：

- 每个目标文件最多保留 10 个版本。
- 版本目录放在 `D:\BakaTOOLS\file-history\`。
- 版本记录写入现有 `gallery.db`，新增 `file_versions` 表。
- 超过上限时删除最旧版本。
- 恢复版本时，先把当前文件保存为一个新版本，再把目标版本替换回来。

#### `electron/ipc/recycle-bin.js`

负责应用内回收站。

规则：

- 回收站目录：`D:\BakaTOOLS\recycle-bin\`。
- 删除时把图片和同名标签文件移动到回收站。
- 回收站记录写入 `gallery.db`，新增 `recycle_items` 表。
- 记录原路径、回收路径、文件类型、删除时间。
- 恢复时移回原路径；如果原路径被占用，则恢复为带序号的新文件。
- 彻底删除时删除回收站文件及其记录。
- 启动时清理超过 30 天的过期项目。

#### IPC 通道

新增或调整以下通道：

- `fs:writeTextSafe`：安全写文本文件。
- `fs:writeBytesSafe`：安全写二进制文件。
- `fs:moveImagesSafe`：带预检、回滚和失败清单的移动/复制。
- `fs:deleteMedia`：移动图片/视频和同名标签到回收站。
- `recycle:list`：列出回收站项目。
- `recycle:restore`：恢复回收站项目。
- `recycle:purge`：彻底删除单个或全部项目。
- `history:list`：列出某文件的历史版本。
- `history:restore`：恢复到某个历史版本。

### 前端

#### 回收站入口

在设置页或图库侧栏增加“回收站”。

界面包含：

- 文件名、原路径、删除时间、大小。
- 恢复按钮。
- 彻底删除按钮。
- 清空过期项目按钮。

#### 历史版本入口

在图片信息面板增加“历史版本”。

用户可以看到：

- 版本时间。
- 恢复该版本。

历史版本对普通用户默认折叠，只在用户需要时打开。

### 移动/复制事务

移动或复制图片时，按以下顺序：

1. 预检所有源文件和目标目录。
2. 生成唯一临时目标名。
3. 复制或移动图片。
4. 移动或复制同名 caption/txt 文件。
5. 更新图库数据库路径。
6. 如果第 3-5 步失败，已移动的文件尝试回滚。
7. 返回成功列表、失败列表。

## 数据表

### `file_versions`

```text
id            INTEGER PRIMARY KEY
target_path   TEXT NOT NULL
version_path  TEXT NOT NULL
created_at    TEXT NOT NULL
```

索引：`target_path, created_at`。

### `recycle_items`

```text
id            INTEGER PRIMARY KEY
original_path TEXT NOT NULL
recycle_path  TEXT NOT NULL
kind          TEXT NOT NULL
size          INTEGER
deleted_at    TEXT NOT NULL
```

索引：`original_path`、`deleted_at`。

## 错误处理

- 所有路径必须先规范化，确保只操作数据目录和用户明确选择的文件。
- 磁盘满、文件被占用、权限不足时，保留原文件并返回错误。
- 回收站恢复遇到原路径冲突时，不覆盖现有文件。
- 批量操作单张失败不中断整批。
- 所有 IPC 返回结构化结果，不向渲染进程抛未处理异常。

## 测试

需要覆盖：

- 安全写入成功。
- 写入中途失败时原文件不变。
- 同一路径并发写入不会损坏。
- 历史版本创建、轮换、恢复。
- 恢复时原路径冲突处理。
- 删除进入回收站、恢复、彻底删除。
- 过期回收站项目清理。
- 移动/复制成功、部分失败回滚、失败清单。
- 路径穿越和越界路径被拒绝。

## 验收标准

1. 模拟磁盘写失败，原标签文件内容不丢失。
2. 删除图片后可在回收站恢复。
3. 修改标签后可恢复到上一个版本。
4. 移动 10 张图片时人为制造 1 张失败，9 张成功且失败清单准确。
5. 超过 30 天的回收站项目在启动时被清理。
6. 相关单元测试和类型检查通过。
