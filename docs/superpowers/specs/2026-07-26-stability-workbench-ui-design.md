# Baka TOOLS 稳定工作台与核心页面优化设计

日期：2026-07-26

状态：用户已确认设计方向，等待书面复核

## 1. 目标

本轮采用“稳定工作台”路线：保留现有粉橙配色、可爱赛博风格、顶部导航和吉祥物，优先修复影响正常使用的问题，再重新组织图库标注、提示词反推、训练中心和首页工作台。

完成后，用户应能顺畅完成以下主流程：

1. 导入或创建数据集。
2. 选择图片并批量标注。
3. 编辑、保存和导出标签。
4. 使用本地模型或云端 AI 反推单张图片。
5. 配置训练参数并通过启动前检查。
6. 提交训练并进入正确任务的监控页面。
7. 关闭并重新打开应用后继续上次工作。

## 2. 本轮范围

| 模块 | 本轮内容 |
|---|---|
| 稳定性 | 修复批量打标、训练任务编号、数据持久化、正式版加载、存储路径、重复监听和 IPC 契约 |
| 首页 | 从功能卡片集合改为带有当前项目、三步进度和最近任务的工作台 |
| 图库与标注 | 采用“数据集—图片—标签”三栏工作区，统一选择、标注、编辑和导出 |
| 提示词反推 | 实现本地标签与云端描述双引擎，分离标签、自然描述和绘图提示词 |
| 训练中心 | 采用“数据集—参数—预检—监控”四步流程 |
| UI 系统 | 统一按钮、表单、状态、进度、空状态和错误恢复方式，减少持续重动效 |
| 打包 | 生成并验证包含当前代码的新安装包 |

高清放大、提示词反推以外的图像工具和 AI 生成功能不重写核心逻辑，只统一入口和基础样式。

## 3. 明确不做

- 不把顶部导航改回侧边栏。
- 不重新设计品牌配色和吉祥物。
- 不引入新的前端 UI 框架。
- 不同时重写高清放大、AI 生成和所有设置页面。
- 不扩展 MCP 工具能力；本轮只处理其访问边界和安全性。
- 不清理与本轮目标无关的历史代码或用户现有改动。

## 4. 整体架构

保留现有 Vue、Pinia、Electron IPC 和本地 Python 训练后端结构，但收紧模块职责：

- Vue 页面只负责展示、输入和用户操作。
- Pinia store 负责页面间可恢复的任务状态。
- preload 只暴露明确、可验证的功能接口。
- Electron IPC 负责文件、数据库、模型进程和训练后端通信。
- 长任务统一使用任务编号、进度事件、完成事件和取消接口。
- 持久数据与临时界面状态分开保存，不再通过清空全部 `localStorage` 模拟清缓存。

### 4.1 长任务状态

标注、训练和运行环境安装采用统一状态：

`idle → preparing → running → cancelling → completed | failed | cancelled | interrupted`

`cancelling` 表示取消请求已收到但后台尚未安全退出；`interrupted` 表示应用或系统异常退出后恢复到的未完成任务。两者都不能伪装成 `cancelled`。

每个任务至少包含：

- `taskId`
- `type`
- `status`
- `completed`
- `total`
- `currentItem`
- `message`
- `startedAt`
- `finishedAt`

任务只能由一个完成处理器结算，避免当前批量标注中多个监听器竞争同一个 Promise。

### 4.2 数据持久化

数据分为三类：

| 类型 | 保存位置 | 示例 |
|---|---|---|
| 业务数据 | SQLite 或业务配置文件 | 图库、标签、数据集、训练任务 |
| 用户设置 | 应用配置文件或稳定的设置键 | 主题、存储位置、默认模型 |
| 临时界面状态 | Pinia 或会话存储 | 当前弹窗、搜索文字、悬停状态 |

关闭应用不再清空业务数据。缓存清理由设置页明确触发，并显示将要删除的内容。

### 4.3 存储路径

默认使用 Electron 提供的系统应用数据目录。用户可以在设置中选择其他目录，例如 `D:\BakaTOOLS`。

首次升级时：

1. 检测旧的 `D:\BakaTOOLS` 数据。
2. 如果旧数据存在，继续使用原目录，避免自动搬迁带来风险。
3. 如果旧数据不存在，使用系统默认目录。
4. 设置页显示当前目录并提供“更改位置”和“打开目录”。

### 4.4 训练运行时边界

运行环境不再由 Electron 重复维护一套安装规则。以所选训练仓库中的 `launcher/core` 为运行时能力来源，`D:\comfyUI\lora-rescripts-study` 作为实现参考；正式版本仍使用 Baka 内置或用户选择的训练仓库，不依赖这条开发机路径。

- 训练仓库负责运行时目录定义、环境检测、完整性检查、显卡兼容性、推荐结果、安装预检、安装计划、进度解析和任务历史。
- Baka 增加轻量 Python 桥接层，把上述能力转换为稳定的 JSON 请求、响应和事件。
- Electron 只负责启动桥接进程、校验参数、转发事件和管理进程生命周期，不再复制运行时清单、脚本顺序和安装判断。
- Vue 只消费统一状态并展示操作，不从日志文字猜测安装是否成功。
- 内置仓库与用户选择的仓库使用同一套接口；仓库能力版本不兼容时先提示升级或切回内置版本，不静默降级到另一套安装逻辑。
- 参考项目中的 `RuntimeCoordinator`、`RuntimeDetector`、完整性检查、安装计划和 `LauncherTaskExecutor` 是对齐目标；只复用任务需要的运行时部分，不把原启动器整页嵌入 Baka。

## 5. 核心功能设计

### 5.1 批量标注

- 修复 worker 初始化后未发送推理命令的问题。
- 删除重复的完成监听器，单一处理器负责返回结果。
- store 保存服务端返回的真实 `taskId`。
- 取消操作校验当前任务编号。
- 进度栏显示完成数量、总数、当前文件、使用的设备和失败数量。
- 任务结束后批量写入图库数据库，并刷新相关图片的标签缓存。
- 部分图片失败时保留成功结果，同时显示可重试列表。

### 5.2 图库扫描与标签保护

- 图片内容或修改时间变化时更新原记录，不删除后重新插入。
- 维持原 `image_id`，确保已有标签继续关联。
- 清理图片时同时清理其标签关系和缩略图。
- 扫描和批量标签写入使用数据库事务。
- 一批操作完成后再保存数据库，避免每条记录都导出整个数据库。
- 数据库异常必须返回错误，不允许查询失败后伪装成空结果。

### 5.3 训练任务

- 提交训练成功后获取 `taskId`。
- 跳转到 `/training/run?taskId=<id>`。
- 监控页优先显示地址中的任务；没有地址参数时显示任务列表。
- 轮询日志、停止任务和状态更新全部使用同一个任务编号。
- 最近任务保存在应用状态中，重启后可继续查看后端仍保留的任务。
- 后端启动不使用固定等待时间；持续检查健康状态，成功或超时后结束等待。

### 5.4 运行环境安装

运行环境安装参考 `D:\comfyUI\lora-rescripts-study` 的分层方式，但不直接复制其界面，也不把参考目录写死到正式程序中。

| 能力 | 采用方式 | Baka 中的表现 |
|---|---|---|
| 运行时清单 | 由训练仓库的运行时目录统一提供 | 显示名称、适用显卡、状态和说明 |
| 环境检测 | 复用检测与完整性检查 | 区分“未准备”“可安装”“已安装”“环境损坏” |
| 自动推荐 | 复用兼容性与推荐结果 | 默认选中推荐项，同时允许手动更换 |
| 安装前检查 | 复用 preflight 和结构化安装计划 | 开始前列出缺少项、将执行的步骤和预计影响 |
| 安装执行 | 复用安装脚本顺序、环境变量、镜像和代理设置 | 顺序执行，实时显示当前脚本、阶段、进度和日志 |
| 状态与历史 | 对齐任务状态、阶段事件和历史记录 | 页面切换或应用重开后仍能查看最后结果 |
| 安装取消 | 在执行层新增受控取消，不沿用当前假取消 | 能停止时真正结束进程树；不能立即停止时在安全点退出 |

安装流程为：

1. 扫描显卡、系统和现有运行时。
2. 显示推荐环境，并解释推荐原因。
3. 执行安装预检；缺少本地 Python 骨架时先调用初始化能力。
4. 展示结构化安装计划，经用户开始后创建唯一任务编号。
5. 桥接层按计划执行脚本并持续发送 `task_state`、`task_stage`、`install_log`。
6. 脚本结束后重新检测环境；只有依赖标记、完整性检查和实际探测均通过才显示安装成功。
7. 保存任务结果和日志摘要，训练预检立即使用最新状态。

取消行为必须与真实进程一致：

- 执行层保存当前安装子进程句柄和取消令牌。
- 点击取消后先进入 `cancelling`，停止启动后续脚本。
- 可安全终止的步骤先请求正常退出，超时后结束该安装进程树。
- 不适合中途打断的步骤显示“正在完成当前步骤，之后停止”，到脚本边界再结束。
- 取消后重新检测运行时；已写入的有效依赖不主动删除，临时文件按安装器约定清理。
- 只有进程确实退出且后续步骤未再执行时才进入 `cancelled`；终止失败则显示 `failed` 和处理建议。
- 参考项目当前没有安装取消接口，因此本能力属于 Baka 的明确扩展，不能只修改前端文字冒充完成。

桥接接口至少覆盖：

| 类型 | 接口或事件 |
|---|---|
| 查询 | 运行时清单、扫描结果、推荐结果、兼容性、预检、安装计划、健康报告 |
| 操作 | 初始化、安装、取消安装、卸载、选择运行时 |
| 状态 | 当前任务、任务历史、是否正在安装 |
| 事件 | 任务快照、阶段变化、安装日志、最终结果 |

现有 `runtime:installCancelled` 不再由 Electron 提前发送。统一由桥接层最终任务结果驱动；如果保留该事件，它只能在任务真实进入 `cancelled` 后发送，并必须同时登记发送端和监听端。

### 5.5 双引擎提示词反推

反推支持三种运行方式：

| 模式 | 输出 |
|---|---|
| 本地标签 | 使用本地 ONNX 模型生成 Danbooru/WD14 标签 |
| 云端描述 | 使用已配置的视觉模型生成自然语言描述和绘图提示词 |
| 双引擎 | 同时运行两者，并分别展示结果 |

具体行为：

- 支持从电脑选择图片，也支持从图库将图片发送到反推页。
- 本地模式传入真实绝对路径、选中的模型路径、CSV 路径、阈值和 provider。
- 云端模式保留服务端返回的自然描述，不再将描述错误拆成标签。
- 结果分成“标签”“自然描述”“绘图提示词”三个区域。
- 标签支持删除、补充、搜索和调整顺序。
- 三类结果分别提供复制按钮。
- 可将标签或提示词保存为图片同名 `.txt`。
- 图库图片可将标签写回图库数据库。
- 保留最近一次结果，页面切换后仍可恢复。
- 未配置模型或 API 时不发送无效请求，直接显示配置入口和缺失项。
- 第一轮只支持单张反推；批量标注继续由图库页承担。

## 6. 页面设计

### 6.1 首页工作台

首页围绕“继续工作”组织，而不是平铺所有功能：

- 当前数据集和上次操作。
- “整理图片 → 自动标注 → 开始训练”三步进度。
- 继续上次任务的主要按钮。
- 最近标注、反推和训练任务。
- 图库数据库、标注模型和训练后端的简明状态。
- 吉祥物用于提示下一步，不遮挡主要操作。

### 6.2 图库与标注

采用三栏布局：

- 左栏：数据集与图库根目录。
- 中栏：搜索、筛选、选择和图片网格。
- 右栏：当前图片标签、补充标签、保存和导出。

长任务进度固定显示在页面底部，但不覆盖图片内容。窗口较窄时，左右栏改为可展开区域。

### 6.3 提示词反推

采用左右布局：

- 左侧：图片预览、来源和引擎选择。
- 右侧：标签、自然描述、绘图提示词和保存操作。

结果区域可编辑。自然描述和绘图提示词使用多行文本框，标签使用可删除标签块。

### 6.4 训练中心

顶部显示四个步骤：

1. 选择数据集。
2. 训练设置。
3. 启动预检。
4. 运行监控。

常用参数直接显示，高级参数折叠。右侧预检区显示数据集、模型、运行环境、磁盘和后端状态。存在致命错误时禁用启动按钮，并提供对应修复入口。

### 6.5 导航与视觉

- 保留顶部导航。
- 一级入口为工作台、图库与标注、LoRA 训练、工具和设置。
- 提示词反推位于工具菜单，并可从图库直接进入。
- 保留深浅主题、粉橙强调色和吉祥物。
- 减少持续扫光、粒子和大面积辉光。
- 所有持续动效遵守“减少动态效果”设置。
- 功能图标使用统一线性图标，emoji 仅用于装饰文案。

## 7. 错误处理

所有失败必须回答三个问题：

1. 发生了什么。
2. 哪些数据或任务受到影响。
3. 用户下一步可以做什么。

统一错误类型：

| 类型 | 展示方式 |
|---|---|
| 输入不完整 | 字段附近提示并聚焦缺失字段 |
| 模型或 API 未配置 | 页面内引导，提供设置入口 |
| 后端未启动 | 状态区提示，提供启动入口 |
| 单项处理失败 | 保留成功结果，列出失败项并允许重试 |
| 数据库或文件写入失败 | 明确显示未保存，禁止显示成功提示 |
| 应用级异常 | 状态栏与可展开详情，保留错误日志 |

禁止关键流程使用空 `catch` 或把数据库异常返回为空列表。

## 8. 安全与正式版行为

- 开发模式加载 `http://localhost:5173`。
- 正式版直接加载打包后的 `dist/renderer/index.html`。
- 正式版不探测或加载开发端口。
- 限制主窗口导航和新窗口打开，只允许应用页面与明确的本地训练地址。
- IPC 文件接口验证参数类型和允许范围。
- MCP 服务继续只监听 `127.0.0.1`，增加身份令牌或来源验证，并限制跨域访问。
- preload 的事件监听接口返回解除函数，页面卸载时调用解除函数。

## 9. 测试设计

### 9.1 自动测试

- 批量标注：初始化、开始、完成、部分失败、取消和 worker 崩溃。
- 标签存储：图片修改后重扫不丢标签。
- 数据库事务：批量写入失败时不留下半批数据。
- 数据持久化：正常关闭和重启后数据集清单仍存在。
- 训练路由：提交后带正确任务编号进入监控页。
- 训练轮询：日志和停止操作使用当前任务编号。
- 反推本地模式：传入真实图片和模型路径。
- 反推云端模式：标签、自然描述和提示词保持独立。
- 运行时桥接：训练仓库返回的清单、推荐、预检和安装计划正确转换，未知字段不会导致页面崩溃。
- 运行时检测：覆盖未准备、可安装、已安装、损坏和检测失败。
- 运行时安装：只有脚本成功且安装后复检通过才进入 `completed`。
- 安装取消：覆盖脚本开始前取消、运行中可中止、当前步骤后停止、终止失败和取消后复检。
- 任务恢复：应用重开后可恢复安装中的快照，并把异常中断任务登记为 `interrupted`。
- IPC 契约：所有使用通道均登记，发出事件有对应监听或明确说明。

### 9.2 手工验收

- 开发模式正常启动。
- 打包后的安装版不依赖 5173 端口。
- 没有 D 盘的电脑可首次启动并使用图库。
- 旧 `D:\BakaTOOLS` 用户升级后仍能看到原图库。
- 断网时本地标注和本地反推可用。
- API 未配置时云端反推显示引导。
- 反复进入和离开核心页面不会出现重复日志或重复进度。
- 运行环境页给出的推荐、安装步骤和最终状态与训练仓库实际检测一致。
- 安装过程中切换页面再返回，进度、日志和任务编号保持一致。
- 点击取消后不会继续启动下一条安装脚本，最终状态与后台进程是否退出一致。
- 强制关闭应用后重开，未正常结束的安装任务显示“意外中断”，不显示成功或已取消。
- 减少动态效果开启后，持续背景动画停止。

## 10. 实施阶段

| 阶段 | 内容 | 阶段验收 |
|---|---|---|
| 1 | 稳定性、持久化、正式版加载、存储路径、IPC；按参考项目收口运行时桥接、检测、安装状态和真实取消 | 类型检查、构建、基础测试通过；运行时状态与训练仓库一致，安装成功、失败、取消和中断均可复现 |
| 2 | 数据库事务、图库扫描、批量标注、三栏布局 | 重扫不丢标签，批量标注可完成和取消 |
| 3 | 双引擎反推与结果保存 | 本地、云端和双引擎分别可用 |
| 4 | 训练四步流程和任务监控 | 提交、日志、状态和停止使用同一任务 |
| 5 | 首页工作台、共享 UI 状态和动效收口 | 四个核心页面风格与交互一致 |
| 6 | 安全收口、安装包和完整回归 | 新安装与旧数据升级场景通过 |

每个阶段独立完成测试和验收，不把所有改动堆到最后一次验证。

## 11. 完成标准

- 已发现的四个核心断点全部有回归测试并修复。
- 图库、反推和训练主流程可以从界面完整走通。
- 应用正常退出不会丢失数据集和最近任务。
- 图片重新扫描不会丢失标签。
- 正式安装版不加载开发服务器。
- 默认存储不依赖 D 盘，旧用户数据保持可用。
- IPC 契约检查通过。
- 运行环境定义、推荐、预检和安装结果以训练仓库核心为唯一依据，Electron 不再维护重复规则。
- 安装取消能真实停止当前任务或在明确的安全点停止，不再出现后台继续运行但界面显示已取消。
- 应用重开后能恢复运行时任务历史，并把非正常退出准确标记为中断。
- 四个核心页面遵循同一套状态、表单和错误设计。
- 新安装包通过首次启动、旧数据升级、断网和重复导航验收。
