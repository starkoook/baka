# 图片工作台、本地引擎与缺失节点管理器设计

- 日期：2026-08-12
- 状态：用户已确认方向
- 目标版本：baka-tools 0.1.0
- 替代范围：本规格替代 `2026-08-11-libtv-style-nodes-design.md` 中“图片节点内嵌生成器”和“生成结果派生新图片节点”的设计。

## 1. 目标

让普通用户能把图片直接拖进画布，自动得到一个职责单一的图片加载节点；需要 AI 修改时，再连接独立的 AI 图片编辑节点。图片带有生成元数据时，工具箱自动读取可复用参数，并在本机 ComfyUI 缺少工作流节点时引导用户进入依赖管理器。

本地运行采用首次使用向导：自动检测或让用户选择 ComfyUI、WebUI/Forge 的安装目录，然后保存后续运行、模型、输出和插件操作所需的路径。

## 2. 本期范围

本期实现：

1. 将现有“图片节点”改为“加载图片”节点，移除节点内嵌的 AI 生成器和图片工具。
2. 新增独立的“AI 图片编辑”节点，接收上游图片并在节点内显示编辑结果。
3. 支持把本地图片文件直接拖进画布，并在落点自动生成加载图片节点。
4. 读取 PNG 中的 ComfyUI、Stable Diffusion WebUI/Forge、NovelAI 生成元数据；其他图片至少读取文件名、格式和尺寸。
5. 将兼容的提示词、模型和尺寸应用到 AI 图片编辑节点，但不自动开始生成，也不覆盖用户已经手动修改的字段。
6. 新增本机 ComfyUI/WebUI/Forge 首次配置向导与引擎档案。
7. 新增 ComfyUI 缺失节点依赖管理器，支持查看缺失项、项目来源、Git 拉取/更新和显式安装依赖。
8. 在画布右上角显示可跳转到依赖管理器的缺失节点通知。

本期不做：

- 管理另一台电脑上的 ComfyUI 文件和插件。
- 自动重建并运行图片里完整的原始 ComfyUI 工作流。
- 静默执行 Git、Python 依赖安装或来源不明的脚本。
- 把 ComfyUI 自定义节点当成 baka-tools 自定义 JSON 节点导入。
- 内置或打包完整的 ComfyUI/WebUI 发行版。

## 3. 交互设计

### 3.1 加载图片节点

节点名称为“加载图片”，只负责：

- 选择本地图片。
- 接收从系统拖入的图片。
- 预览、替换和保存当前图片。
- 显示尺寸、格式以及“含生成元数据”标记。
- 展开查看读取到的提示词、模型、Seed、采样器、尺寸和生成器等信息。
- 向后续节点输出图片及标准化元数据。

节点内不再出现 API 配置、模型选择、生成提示词、生成按钮、裁切、切片、高清、扩图或重绘工具。

### 3.2 AI 图片编辑节点

节点名称为“AI 图片编辑”，包含：

- 一个必需的图片输入口和一个图片输出口。
- API/本地引擎选择、模型、编辑要求、输出尺寸。
- “开始编辑”按钮、运行状态、错误状态和结果预览。
- 结果保留在当前节点内并作为输出继续连接后续节点，不自动创建派生图片节点。

当连接带元数据的加载图片节点时：

- 编辑要求为空时，自动填入原图正向提示词作为可编辑参考。
- 模型为空且当前引擎存在同名模型时，自动选中该模型；不存在时只显示原模型名称，不伪装成可用模型。
- 输出尺寸未被用户修改时，继承原图尺寸或映射到引擎支持的最近尺寸。
- Seed、采样器、CFG、Steps 等暂不受当前编辑接口支持的参数会被保存和展示，但不强行提交。
- 用户一旦手动修改字段，重新连线或重新读取元数据不得覆盖用户输入。

### 3.3 系统图片拖入

用户把一个或多个图片文件拖到画布时：

- 每张图片在对应落点附近生成一个加载图片节点，多张图片按固定间距排列。
- 非图片文件被忽略，并显示一次简短提示。
- 文件读取失败只影响对应文件，不撤销其他已成功创建的节点。
- 节点创建纳入撤销、重做和自动保存。
- 从工具箱资产面板拖入图片继续沿用现有行为，并补上相同的元数据读取流程。

## 4. 元数据读取与应用

### 4.1 支持格式

PNG 读取 `tEXt`、`iTXt` 和 `zTXt` 文本块，识别：

- ComfyUI `prompt` 与 `workflow`。
- A1111/Stable Diffusion WebUI 和 Forge 的 `parameters`。
- NovelAI 的 `Comment`。

JPEG、WebP、GIF 等格式本期只保证基础文件信息和尺寸；没有可识别生成元数据时，不显示空的参数区域。

### 4.2 标准化结果

元数据解析器输出统一结构：生成器、正向提示词、反向提示词、模型、宽高、Seed、Steps、CFG、采样器、VAE、CLIP、LoRA、原始工作流、工作流节点类型和节点来源提示。

解析失败不阻止图片加载。错误只记录为“元数据不可读取”，图片节点仍可正常使用。

### 4.3 缺失节点来源解析

项目地址按以下优先级确定：

1. 工作流节点属性中明确携带的仓库地址。
2. 工作流中的 Comfy Registry 标识，例如 `cnr_id` 或等价来源标识。
3. 本地缓存的官方 Comfy Registry / ComfyUI-Manager 节点映射。
4. 无法可靠确定时标记为“未知来源”。

同一节点类型匹配多个项目时，全部显示为“可能来源”，不自动选择，不允许一键安装全部候选。

## 5. 本地引擎首次配置

### 5.1 触发时机

不在应用启动时强制弹出。只有用户第一次选择本地运行，或在依赖管理器里尝试安装 ComfyUI 节点时，才打开配置向导。

### 5.2 配置流程

1. 选择 ComfyUI 或 WebUI/Forge。
2. 自动探测默认本地端口和常见安装位置。
3. 探测成功时展示识别结果并让用户确认；失败时让用户选择安装主目录。
4. 验证目录结构、启动入口和 Python 环境。
5. 自动推导并保存 API 地址、启动入口、Python、插件、模型和输出目录。
6. 测试连接并显示“已连接”或明确的失败原因。

### 5.3 引擎档案

每个本地引擎档案保存：类型、显示名称、安装根目录、API 地址、启动入口、Python 路径、插件目录、模型目录、输出目录、最后验证时间和健康状态。

ComfyUI 档案额外保存 `custom_nodes` 路径。WebUI/Forge 档案保存 `extensions` 路径，但不显示 ComfyUI 缺失节点安装功能。

路径必须通过主进程验证。渲染进程不能自行拼接或写入未经验证的任意目录。

### 5.4 本地运行

- 已运行的引擎直接连接。
- 配置了本机路径但未运行时，可由用户点击启动；工具箱后台启动并等待端口就绪。
- AI 图片编辑节点可选择云端 API 或已配置的本地引擎。
- ComfyUI 通过最小兼容工作流执行图片编辑；WebUI/Forge 通过其 img2img API 执行。
- 引擎不可用时保留节点参数和上次结果，不清空画布。

## 6. ComfyUI 缺失节点依赖管理器

### 6.1 入口与通知

读取到 ComfyUI 工作流后，使用已连接 ComfyUI 的节点清单判断缺失项。存在缺失项时，画布右上角显示持久通知：

> 检测到 3 个缺失节点 · 查看依赖

点击通知打开“ComfyUI 节点依赖”控制面板，并自动定位到当前图片对应的检查结果。自动保存等短消息继续使用原有轻量提示，不与依赖警告混在一起。

未配置 ComfyUI 时，通知显示“图片含 ComfyUI 工作流 · 配置本地引擎”，点击进入首次配置向导。

### 6.2 面板内容

面板按状态分组：

- 已安装：ComfyUI 当前已经提供该节点类型。
- 缺失且找到唯一项目：显示节点类型、项目名称、仓库地址和“Git 拉取”。
- 缺失且存在多个候选：列出候选地址，要求用户先选择。
- 缺失但来源未知：显示节点类型和“复制名称”，不提供伪造链接。
- 已拉取待重启：代码已存在，但 ComfyUI 尚未重新加载。
- 依赖缺失：检测到 `requirements.txt`，等待用户确认安装。

### 6.3 Git 与依赖操作

- 首次安装使用 Git clone 到已验证的 ComfyUI `custom_nodes` 子目录。
- 已存在且远端地址一致时提供“更新”，执行快进更新；存在本地修改或远端不一致时停止并说明原因。
- 只有 GitHub 仓库地址可以直接拉取；普通项目网页只能打开查看。
- 拉取成功后扫描 `requirements.txt`。存在依赖时显示单独的“安装依赖”按钮和风险说明。
- 安装依赖必须使用该 ComfyUI 档案识别出的 Python，不使用系统默认 Python。
- 不自动执行仓库中的 `install.py`。本期只支持用户确认后的 `requirements.txt` 安装。
- 安装或更新完成后提示重启 ComfyUI，再重新检查缺失节点。
- 每个操作显示实时阶段、最终结果和可复制的错误摘要。

## 7. 组件边界

为避免继续扩大 `Workbench.vue`，新增能力拆成独立单元：

- 元数据解析器：读取图片块、标准化生成参数和工作流来源提示。
- 画布拖入协调器：验证文件、读取图片、计算节点落点并返回节点创建数据。
- 引擎档案服务：探测、验证、保存和启动本地引擎。
- ComfyUI 适配器：读取 `/object_info`、执行最小图片编辑工作流并检查节点类型。
- WebUI/Forge 适配器：健康检查、模型读取和 img2img。
- 缺失节点解析器：把工作流节点类型映射成已安装、候选项目或未知来源。
- Git 安装服务：只在验证过的插件目录内 clone/pull，并返回结构化进度。
- 首次配置向导、依赖通知和依赖管理面板：分别负责 UI，不直接操作文件系统或子进程。

现有 baka-tools JSON 节点管理器保留，但改名为“Baka 自定义节点”，与“ComfyUI 节点依赖”分开展示。

## 8. 错误与安全规则

- 所有安装目标必须解析为 ComfyUI `custom_nodes` 下的直接子目录，禁止越界路径和目录穿越。
- Git 和 Python 通过参数数组启动，不拼接 shell 字符串。
- 网络查询失败时使用缓存；没有缓存则保留未知来源状态，不阻止图片加载和云端编辑。
- 目录选择错误时给出可理解的原因，并允许重新选择。
- 端口连接成功但目录不可写时，可以运行，但依赖管理器进入只读状态。
- 安装失败不得删除已有仓库或用户文件。
- 不在工作流保存文件中写入 API Key、系统 Python 凭据或其他秘密。

## 9. 验证标准

自动测试覆盖：

- PNG 三类文本块和四种生成器元数据的正常、缺失、损坏情况。
- ComfyUI 工作流节点类型、唯一来源、多候选和未知来源映射。
- 图片单张/多张拖入、非图片过滤、落点排列和撤销数据。
- 元数据只填空字段，不覆盖用户编辑。
- 本地引擎路径识别、错误目录、不可写目录和档案保存。
- Git 目标越界拦截、首次拉取、同源更新、远端冲突和依赖检测。
- ComfyUI `/object_info` 与 WebUI/Forge 健康检查、模型读取和图片编辑请求。
- 右上角通知跳转到正确依赖检查结果。

交付前运行完整单元测试、类型检查、IPC 通道检查和生产构建，并在 Electron 窗口手动验证以下流程：

1. 拖入普通图片，自动生成加载图片节点。
2. 拖入带 ComfyUI 元数据的 PNG，参数可查看并能应用到 AI 图片编辑节点。
3. 配置本机 ComfyUI，检测缺失节点并从通知进入依赖管理器。
4. Git 拉取一个测试节点，确认依赖步骤不会静默执行。
5. 重启 ComfyUI 后重新检查，缺失状态更新。
6. 使用云端 API、ComfyUI 和 WebUI/Forge 分别完成一次 AI 图片编辑。
