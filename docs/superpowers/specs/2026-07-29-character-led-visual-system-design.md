# Baka TOOLS 角色主视觉美术系统设计

日期：2026-07-29  
状态：待用户书面确认后进入实施计划

## 1. 设计结论

Baka TOOLS 采用“角色主视觉主页 + 专业创作工作区”的视觉系统。

主页通过现有角色插画建立品牌记忆；图库、标注、训练器和设置页不重复使用大横幅，而是根据工作任务采用更紧凑、更专业的布局。整体不再沿用“可爱赛博 HUD”作为全局语言，也不直接临摹音乐播放器参考图。

## 2. 目标

1. 用户首次打开软件时，能够立刻记住角色和 Baka 品牌。
2. 长时间整理图片、标注和训练时，界面保持安静、清晰、耐看。
3. 主页、图库、标注和训练器视觉相关，但各自为对应任务服务。
4. 保留完整 LoRA 训练能力，不因视觉简化而隐藏或丢弃参数。
5. 适合未来打包给其他用户，避免依赖开发机资源和未确认授权的运行时。

## 3. 非目标

- 本轮不制作真正的 Live2D 模型。
- 本轮不开放任意 Live2D 模型导入。
- 本轮不让小人出现在图库、标注、训练器或设置页。
- 本轮不重做现有 LoRA 训练后端。
- 本轮不照搬参考图中的品牌、人物、图标或音乐播放器结构。

## 4. 美术方向

### 4.1 品牌气质

关键词：编辑感、作品感、清爽、安静、带角色个性。

专业感占 75%，角色个性占 25%。角色负责建立情绪和记忆点，界面负责承载工作，不让装饰干扰操作。

### 4.2 色彩

| 用途 | 建议方向 |
| --- | --- |
| 主背景 | 暖白或低饱和浅灰，不使用纯白大面积直射 |
| 主文字 | 接近黑紫的深色，提高可读性并呼应角色发色 |
| 品牌色 | 低饱和薰衣草紫 |
| 操作强调 | 少量珊瑚粉，仅用于主按钮、选择和关键进度 |
| 成功 / 警告 / 错误 | 独立语义色，不使用品牌色替代状态色 |
| 深色区域 | 仅训练日志、曲线画布和图片沉浸查看使用 |

图片和人物是页面的主要色彩来源。普通 UI 不使用多色渐变、霓虹描边、扫描线、粒子或持续发光。

### 4.3 字体与图标

- 中文正文使用现代无衬线字体，优先系统字体或可随安装包合法分发的字体。
- 英文和数字使用 Inter 风格的中性无衬线字体。
- 页面标题不使用卡通字体。
- 图标统一采用线性图标，常规尺寸 16–20px。
- emoji 只允许出现在角色台词中，不承担功能识别。

### 4.4 形状与层级

- 普通控件圆角 8px，面板 10–12px，主页横幅可使用 20–24px。
- 卡片只用于独立项目、数据集和可点击入口，不使用“每一块内容都是卡片”的结构。
- 内容层级主要通过留白、字号、分隔线和区域叠放建立。
- 阴影保持轻微；弹窗和主页悬浮内容区允许更明显的层级阴影。

## 5. 应用外壳

### 5.1 导航

- 使用固定左侧导航，不再使用占据内容顶部的大型功能展示。
- 第一层只保留：主页、图库、标注、训练、工具、设置。
- 当前页面通过浅色背景块和图标变化表示，不使用强烈辉光。
- 导航底部显示版本、运行环境状态和用户设置入口。

### 5.2 顶部区域

- 普通工作页顶部高度控制在 48–64px。
- 只保留页面名、当前对象、搜索和当前页面最重要的操作。
- 不重复放置欢迎语、宣传标语和统计卡片。

## 6. 页面设计

### 6.1 仪表盘

仪表盘是唯一使用大幅角色主视觉的页面。

结构：

1. 顶部角色横幅占首屏约 36%–42%。
2. 左侧放欢迎语、当前数据集状态和一个主操作“继续工作”。
3. 右侧放角色主视觉，保证脸部和上半身不被按钮覆盖。
4. 下方浅色工作区向上覆盖横幅 20–32px，形成参考图中的编辑式叠层。
5. 工作区优先展示“继续处理”“最近数据集”“最近训练”三类内容，不展示无行动价值的指标墙。

小人规则：

- 使用 `public/mascot.png` 中的现有角色形象。
- 当前源图为 800×533，正式横幅需要扩展或重绘为至少 1920×720，推荐制作 2400×900 主文件。
- 人物置于右侧，左侧保留约 40% 安全文字区域。
- 第一阶段只做轻微镜头漂移、1.00–1.03 呼吸缩放和鼠标视差。
- 禁止整个人物在页面内来回走动、弹跳或随机遮挡文字。
- `prefers-reduced-motion` 下停用全部装饰运动。

### 6.2 图库

图库采用 Eagle 与 Lightroom 类似的任务结构，但使用 Baka 自己的视觉语言：

- 左侧 200–240px：素材库、智能分类、文件夹和状态数量。
- 中央：图片优先的自适应网格，默认不为每张图添加厚重卡片背景。
- 右侧 280–320px：所选图片的缩略图、标签、标注状态和文件信息。
- 顶部只保留搜索、筛选、排序、网格大小和导入。
- 保留空白区域拖入、文件拖入和文件夹拖入。
- 图片悬停只显示选择、收藏和状态，不永久覆盖大量按钮。

### 6.3 标注

标注页与图库分开设计，只传递数据集路径、选择项和完成状态：

- 中央使用最大化图片画布。
- 右侧为 caption 和标签编辑区。
- 底部为胶片条、上一张/下一张和完成进度。
- 顶部显示数据集名称、自动保存状态、反推入口和异常数量。
- 常用操作必须支持键盘快捷键，但界面仍保留可见按钮。
- 反推结果先预览再覆盖，避免破坏人工标注。

### 6.4 训练器

训练器采用专业工作台结构，不套用主页横幅：

- 顶部为基础、完整、原版兼容三种模式切换。
- 左侧为训练步骤与配置分组。
- 中央为当前分组参数。
- 右侧为数据集摘要、显卡与环境状态、启动前检查和预计输出。
- 训练开始后，中间区域切换为进度、loss、速度、显存、温度、样图与日志。
- 日志区允许深色背景，但参数表单保持与应用主视觉一致。
- Schema 未识别字段必须显示兼容提示，不能静默丢弃。

### 6.5 元数据查看

- 双击图片打开居中详情层，建议宽度为当前窗口的 76%–84%。
- 左侧约 56% 展示图片，右侧约 44% 展示信息。
- 信息按“生成参数、模型、文件、标签、原始数据”分组。
- 常用字段提供单独复制按钮，完整原始数据放在折叠区。
- 图片区域允许缩放和拖动，按 Esc 关闭。

### 6.6 设置与工具

- 使用列表和分组表单，不使用大面积彩色卡片墙。
- 危险操作放在独立分组，使用语义色和二次确认。
- 训练器组件、运行环境和更新源分别显示版本与占用空间。

## 7. 角色素材路线

### 第一阶段：主页横幅

保留当前角色身份和服装，将现有插画扩展为宽幅高清主视觉。优先补画背景和画面边缘，不改变人物脸部、发色和服装特征。

交付素材：

- 2400×900 主横幅 PNG。
- 1920×720 WebP 或 PNG 运行版。
- 1200×600 小窗口裁切版。
- 左侧文字安全区标注图。
- 静态降级图。

### 第二阶段：轻量动态

在不拆分人物五官的前提下加入镜头漂移、背景视差和轻微呼吸缩放。所有效果由界面完成，不修改源图，不增加 Live2D 运行时。

### 第三阶段：独立 Live2D 资产

如后续需要真正的眨眼、张嘴、转头和表情，使用当前角色作为设定参考，重新绘制正面半身分层立绘并在 Cubism Editor 中绑定。该模型与主页横幅是两个资产，不强行拆解当前自拍构图。

若应用未来允许用户导入任意 Live2D 模型，必须在公开发布前完成 Live2D 对“可扩展应用”的授权评估。

## 8. 组件边界

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| `BrandHero` | 主页横幅、文字安全区、角色背景和轻量动效 | 图库和训练状态详情 |
| `WorkspaceHeader` | 普通页面标题、对象状态和主操作 | 品牌宣传 |
| `GallerySidebar` | 图库分类与文件夹 | 标注编辑 |
| `GalleryGrid` | 图片布局、选择与拖入反馈 | 元数据编辑 |
| `GalleryInspector` | 所选图片摘要 | 全屏元数据查看 |
| `AnnotationWorkspace` | 图片、caption、标签和进度 | 图库组织 |
| `TrainingWorkbench` | 参数、预检和训练状态 | 训练后端实现 |
| `MetadataViewer` | 双击详情、复制和原始数据 | 修改训练配置 |

页面之间只传递数据集路径、选择项和状态，不共享页面布局或互相嵌套工作区。

## 9. 动效规则

- 控件反馈 120–180ms，页面内容切换 180–240ms。
- 只对用户操作和状态变化做动画。
- 禁止循环扫描线、粒子漂浮、持续辉光和大范围鼠标视差。
- 训练进行中的动画只用于进度表达。
- 系统开启减少动态效果时，保留必要状态变化，移除所有装饰动画。

## 10. 响应与窗口尺寸

- 主要设计基准：1440×900。
- 最低可用窗口：1100×720。
- 小于 1200px 时允许收窄或折叠左侧导航和右侧检查器。
- 主页横幅必须准备宽屏与小窗口两种裁切，人物脸部不得被裁掉。
- 训练器在小窗口下优先保留参数和启动检查，次要摘要移入抽屉。

## 11. 验收标准

1. 仪表盘首屏能看到角色、继续工作和最近项目，且没有统计卡片墙。
2. 小人只在仪表盘出现，任何工作页都不渲染角色组件。
3. 图库标题区不超过 64px，拖拽导入仍可用。
4. 图库、标注、训练器在视觉上属于同一产品，但布局互不复制。
5. 双击元数据查看仍可用，信息分组清晰并支持复制。
6. 训练器三种模式、Schema 参数和启动前检查不因视觉改造丢失。
7. 1440×900 与 1100×720 下没有遮挡、横向溢出或关键按钮不可见。
8. 减少动态效果模式下没有循环装饰动画。
9. 新界面不再出现扫描线、漂浮粒子、全屏辉光或滥用毛玻璃。
10. 新角色横幅在常见窗口尺寸下清晰，人物脸部和左侧文字互不遮挡。

## 12. 实施顺序

1. 建立新的色彩、字体、间距和层级令牌。
2. 制作并验收主页横幅素材。
3. 重做应用外壳与仪表盘。
4. 重做图库与元数据查看。
5. 重做标注工作区。
6. 重做训练器视觉层，不改训练后端协议。
7. 整理设置与工具页。
8. 完成深浅对比、窗口尺寸、键盘操作和减少动态效果验收。

## 13. 参考原则

- 参考音乐类艺术家页面的人物横幅、内容叠层和编辑感。
- 参考 Eagle 的素材分类、图片网格和检查器职责。
- 参考 Lightroom 的网格/详情切换、相册、评分和筛选逻辑。
- 参考 Runway 的主页、工作会话和资产分工。
- 保留 Baka 自己的角色、文案、功能结构和训练能力，不复制任何参考产品的品牌资产或页面。
