## 2. 问题清单

### 2.1 性能 / 占用（按影响排序）

1. **主进程被系统监控卡死（已修复）**：首页每 2 秒同步执行 `nvidia-smi`（最多阻塞 3 秒），没有 N 卡的机器还会反复跑更慢的 `wmic`。期间所有 IPC（缩略图、对话框、标注）排队等待——这是"卡顿"的头号来源。CPU 读数还是开机以来的平均值而不是实时负载。
2. **图片全部走 base64 IPC**：图库缩略图、大图预览、标注页图片、工具封面等都是"主进程同步读文件 → base64（体积 +33%）→ IPC 复制 → 渲染端 data: URL 常驻内存"。1000 张图约多占 40 MB 字串内存，滚动时主进程同步读盘。`media://` 协议已经注册且在工作台里用得很好，只是其它页面没用上。
3. **首页视觉层动画开销**：`filter: blur(110px)` 的环境光、随滚动逐帧改变的 `filter: saturate()` + `transform`、封面图 12 秒无限"呼吸"缩放、`perspective` 3D 上下文、`:has()` 悬停时给相邻大块打 `filter`。这些在集显 / 高分屏上明显掉帧。
4. **工具选择器**：9 张全屏海报 `<img>` 同时挂在 DOM 里，每次打开都通过 IPC 重新读 base64；卡片悬停 `scale(1.12)` + 大阴影。
5. **图库网格没有虚拟滚动**：千张以上时 DOM 节点与解码位图线性增长。
6. **`Workbench.vue` 4297 行 / 138 KB 单文件**（脚本 2348 行）：难维护、编译慢，任何小改都全量重编译。
7. 系统监控数值用 `:key` 强制重建 DOM 触发动画，每 2 秒重建 3 个节点。
8. 安装包携带约 3.9 MB 无用资源（见 1.1）。

### 2.2 可用性 / 信息架构

1. **导航路径太长**：侧栏只有"首页"和"控制台"，9 个工具全部藏在全屏"工具选择"覆盖层里，进任何工具都要 2 步，且没有"当前在哪个工具"的常驻指示。
2. **工具选择器显示假数据**：`1,284 张图片`、`36 待处理`、`E03 20 轮·进行中`、`12 排队中` 全是写死的占位值；4 个工具共用同一张 `upscale.jpg` 海报。
3. **页面语言不统一**：首页 / 设置 / 图库是新版"编辑风"（紫色、无边框），在线画廊仍是旧"粉橙 HUD"（`BOORU COLLECTION` 胶囊、发光），标注页是深色 HUD，训练页是又一套折叠面板样式。
4. 在线画廊工具栏在 1024 px 宽时横向溢出（"设置""+ 图站"被裁掉）。
5. `/reverse`、`/generate` 两个页面无处可进。
6. `docs/ui-design-system.md` 描述的是粉橙 HUD + ZCOOL 字体，与代码（紫色编辑风 + Inter）已脱节，新人会被误导。

## 3. 设计方案

### 3.1 三条路线（沿用 9 月 20 日上一轮头脑风暴的 A/B/C）

| | A · 创作工作室封面 | **B · GitHub 式工作台（推荐）** | C · 赛博舱体 + 小人 |
| --- | --- | --- | --- |
| 首页 | 大图封面 + 一个主按钮，像启动器 | 常驻左侧导航 + 紧凑首页（继续工作 / 真实统计 / 最近项） | 粉橙 HUD、舱体边框、吉祥物陪伴 |
| 品牌感 | 强 | 中（靠一张克制的封面插画 + 紫色主色维持） | 最强 |
| 好用 | 中：进工具仍要经过封面 | **高**：任何工具 1 步可达，Ctrl+K 全局跳转 | 中 |
| 占用 / 流畅 | 中 | **最低**：只用 opacity / transform 动效，无模糊无粒子 | 最高，光效必须克制否则拖流畅度 |
| 与现有代码距离 | 近（现状就是 A） | 中：换外壳与首页，页面内部复用 | 远：要重做 tokens 与大量组件 |

**推荐 B（含一点 A 的封面）**，理由：Owner 本次明确要求"参考 GitHub 等网站""减轻占用、提高流畅度""功能好用"；B 直接命中三条。品牌插画保留为首页顶部一条 ≤ 36 vh 的静态封面（不呼吸、不模糊、不随滚动变色），既留记忆点又不牺牲性能。

### 3.2 推荐方案细节（B+）

**外壳**
- 标题栏 42 px（保留自绘窗口按钮）+ 左侧导航（默认 220 px 展开，可折叠到 64 px 只留图标）+ 内容区 + 状态栏 30 px。
- 导航分组：首页 ／ 素材：图库、在线画廊 ／ 制作：标注、训练、放大、图像工具、视频工具 ／ 工作台 ／ 底部：控制台、设置。当前页高亮 + 左侧 3 px 指示条（保留现有动效）。
- `Ctrl+K` 命令面板：输入即搜页面与常用动作（导入图片、开始标注、打开回收站……），GitHub 同款交互。图库页目前把 `Ctrl+K` 用作站内搜索，实施时把图库搜索并入命令面板（面板内直接输入标签即搜图），避免双重快捷键。
- 统一 `PageHeader`（标题 / 一句说明 / 右侧动作按钮），所有页面用同一个组件，替换各页私写的头部。

**首页（封面）**
- 顶部封面：现有角色插画裁成横幅，高度 `clamp(220px, 36vh, 320px)`，左侧文案 + "继续工作"主按钮（跳到上次工作区），静态。
- 下方三列真实数据卡：图库（张数 / 来源 / 数据集）、标注（待处理 / 已完成）、训练（当前任务 / 进度）；数据来自现有 store，不再有占位假值。
- 最近项：最近打开的工作区、最近导入的图片（缩略图）。
- 系统监控保留（CPU / RAM / GPU），去掉 `:key` 重建，改 CSS 类切换。
- 去掉：滚动"交接"动画、`perspective`、`blur(110px)` 环境光、封面呼吸。

**工具选择器**
- 不再是主导航；改为"首页封面"的一部分（可选保留为 `Ctrl+Shift+T` 的全屏浏览模式），海报只渲染当前一张 + 预加载下一张，用 `media://` 直接引用文件，不走 base64。

**视觉令牌**
- 保留现在的紫色编辑风 tokens（`--brand-primary #9588ec` 等），删掉无人用的粉橙 HUD 旧别名，`variables.css` 从 250 行收到约 120 行。
- 动效规范：时长 ≤ 200 ms，只允许 `opacity` / `transform`；禁止对 `filter`、`backdrop-filter`、`box-shadow` 做动画；默认不允许无限循环动画（加载指示器除外）；`prefers-reduced-motion` 一律关闭。
- 深 / 浅主题保留。

**功能设计参考**
- 导航与命令面板：GitHub（左栏 + `Ctrl+K`）。
- 图库网格 / 多选 / 详情侧栏：Eagle、Google Photos（虚拟滚动、Shift 范围选、右侧固定详情）。
- 训练页：Kohya GUI / lora-scripts 的分组折叠 + 右侧实时日志（现状已接近，只统一样式）。
- 工作台：ComfyUI / n8n（现状功能保留，只拆文件与统一工具栏）。

### 3.3 性能方案

| 措施 | 预期效果 | 阶段 |
| --- | --- | --- |
| 系统监控非阻塞（已做） | 首页停留时不再每 2 秒卡主进程 | 0 ✅ |
| 图片改 `media://`（缩略图返回路径而非 base64；临时缩略图也落盘缓存） | 千张图库省约 40 MB 内存，滚动时主进程零同步读盘 | 2 |
| 图库网格虚拟滚动 | DOM 与解码内存与可见区成正比 | 2 |
| 首页去滤镜 / 去无限动画 | 集显下首页稳定 60 fps | 1 |
| 工具海报按需渲染 + `media://` | 打开工具页不再一次解码 9 张大图 | 1 |
| `Workbench.vue` 拆分为画布 / 节点 / 侧栏 / 工具栏组件 + composables | 编译与热更新加速，后续改动可局部测试 | 3 |
| 移出安装包无用资源 3.9 MB；卸载 `electron-updater`（已确认运行代码零引用，只剩一条测试断言"不得使用"） | 安装包与启动时 asar 读取减小 | 4 |
